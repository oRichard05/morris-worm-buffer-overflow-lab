WHAT HAPPENED?

One input. Two memory regions.

The computer expected a user name. Our C example shows how a long input can change data that was supposed to stay untouched.

STEP 1 OF 4 24 BYTES

Where does a name go?

The program reserves 16 bytes for the name. Right next to it is another field holding the user's role.

NAME · 16 BYTES ROLE · 8 BYTES

The connection to 1988

The real fingerd service used a 512-byte buffer and a C function called gets(), which did not check the input length. The Morris Worm exploited that error to redirect execution. Our example uses a much smaller buffer and changes a neighboring role field so the problem is easier to see. It does not recreate the original attack.
