CASE FILE / 1988

The Morris Worm

ARCHIVE / 001
02 NOVEMBER 1988A small memory bug helped a worm spread across the early Internet.
01 / ENTRY POINT

UNIX finger service

The historical worm exploited a buffer overflow in the fingerd service, which answered user-information requests.

02 / CONSEQUENCE

Unauthorized execution

The overflow could redirect a program's execution. The actual worm also used other weaknesses to spread.

03 / RESPONSE

Fix the unsafe input

Administrators patched or disabled vulnerable services. Limiting input length was an important part of preventing this class of error.

This lab is a simplified reconstruction, not the original worm or original exploit. Read: RFC 1135 · MITRE CWE-121

SECURITY ENGINEERING / SIDE-BY-SIDE

What does the patch change?

BEFORE / AFTER

The fix checks the size before copying. Repeat the same crafted input against both versions and compare their behavior.

VULNERABLE
Session session = {{0}, "GUEST"};
strcpy(session.name, argv[1]);

Copies input without checking the 16-byte name buffer.

PATCHED
if (strlen(argv[1]) >= sizeof(session.name)) {
    puts("STATUS: INPUT REJECTED");
} else {
    memcpy(session.name, argv[1], strlen(argv[1]) + 1);
}

Checks capacity, including the string terminator, before copying.
